# Content Signal Extraction and Recommendation API

The monolith is gone. What replaced it is five independent services — authentication, YouTube, Reddit, LLM, and an API gateway — each running its own process, owning its own data, and deployable without touching the others.

## What Changed

The original codebase was a single FastAPI app with eight routers and one database. Every request — login, channel fetch, comment analysis, title generation — landed in the same process. That worked until it didn't: Ollama calls blocking comment ingestion, auth migrations coupled to YouTube schema changes, no way to scale the LLM workload independently.

The rewrite split the monolith along its natural seams. Authentication is its own service. YouTube signal extraction is its own service. Reddit trending analysis is its own service. LLM generation is its own service. An API gateway sits in front of all four, routing by path prefix, stripping hop-by-hop headers, and forwarding everything else upstream unchanged.

## Architecture

```
Client
  │
  ▼
api-gateway  :8000   (path-prefix routing via ROUTE_MAP)
  ├── /auth  →  authentication  :8001
  ├── /youtube  →  youtube  :8003
  ├── /reddit  →  reddit  :8002
  └── /llm  →  llm  :8004
```

Every service behind the gateway runs against shared PostgreSQL and Redis instances. The gateway itself holds no state — it's a single `httpx.AsyncClient` that proxies requests, nothing more.

## Services

### API Gateway (`api-gateway/`, port 8000)

Routes all incoming traffic. The `ROUTE_MAP` in `app/core/config.py` maps path prefixes to upstream base URLs; longer prefixes match first. The gateway strips hop-by-hop headers, forwards the body and remaining headers unchanged, and streams the upstream response back to the caller.

No auth logic lives here. The gateway doesn't verify tokens — upstream services do.

Endpoints:
- `GET /health` — liveness check

### Authentication (`authentication/`, port 8001)

Owns user accounts, OTP-based signup, and JWT issuance. Nothing else touches the `users` table.

Endpoints:
- `POST /users/signup/send-otp` — hashes password, generates a 6-digit OTP, stages the payload in Redis under `reg:<email>` (TTL 500s), prints OTP to stdout
- `POST /users/signup/verify-otp` — verifies OTP, inserts user into DB, removes Redis key
- `GET /users/profile` — JWT-required; returns `UserResponse`
- `DELETE /users/profile/delete` — JWT-required; deletes user row, returns 204
- `POST /login` — `OAuth2PasswordRequestForm`; returns `{ token, token_type }`

### YouTube (`youtube/`, port 8003)

Handles everything downstream of a YouTube channel handle: channel discovery, video ingestion, daily metric snapshots, comment ingestion, AI comment analysis, and title recommendations generated by the LLM service.

Migrations run automatically at container start (`alembic upgrade head`). Schema history: 15 linear revisions from initial users table through predicted titles.

Endpoints:
- `POST /channels/` — Redis cache → DB → YouTube API; caches by handle for 7 days
- `POST /videos/store` — fetches upload playlist, inserts new videos (`ON CONFLICT DO NOTHING`), currently one page (20 videos)
- `POST /metrics/` — batches YouTube API calls in chunks of 50 IDs, computes engagement rate `(likes + comments) / views × 100`, upserts by `(video_db_id, date)`
- `POST /fetch-comments` — pages through `commentThreads`, de-duplicates on `comment_id`
- `POST /comment_analysis` — runs async HF Inference API sentiment and toxicity pipeline with VADER and keyword fallbacks
- `POST /video_recommendation/comments` — extracts topics from stored comments, calls Ollama via the LLM service to generate titles, caches results in `predicted_titles`

### Reddit (`reddit/`, port 8002)

Fetches trending Reddit posts, ranks them by `upvotes + 0.5 × comments`, and asks the LLM service to generate one YouTube video idea per post.

Data flows through three tiers: Redis (1-hour TTL) → PostgreSQL (2-hour freshness window) → RapidAPI (`reddit34.p.rapidapi.com`). A cache miss hits the DB first; only if the DB rows are older than 2 hours does the service call the external API.

Endpoints:
- `POST /ideas/reddit` — accepts `{ mode: "general" | "specific", subreddits?: string[] }`; `specific` mode requires 1–3 subreddits, fetches them concurrently and merges; returns top 10 posts with trend scores and one video idea per post

### LLM (`llm/`, port 8004)

A thin wrapper around Ollama. Accepts a prompt and optional system message, calls `{OLLAMA_BASE_URL}/api/chat` with `stream: false`, returns the content. The model is configured via `LLM_MODEL` in the environment — the docker-compose default is `tinyllama`.

This service exists so that Ollama is called from one place. The YouTube and Reddit services both reach it over HTTP rather than calling Ollama directly.

Endpoints:
- `POST /generate` — `{ prompt: string, system?: string }` → `{ text: string }`
- `GET /health` — liveness check

## Running Locally

```bash
docker compose up --build
```

The compose file starts all five services plus PostgreSQL 15, Redis 7-alpine, and Ollama. Ollama pulls `tinyllama` on first boot. YouTube and Reddit services run `alembic upgrade head` before starting uvicorn.

Service URLs after `docker compose up`:

| Service        | URL                       |
|----------------|---------------------------|
| API Gateway    | http://localhost:8000     |
| Authentication | http://localhost:8001     |
| Reddit         | http://localhost:8002     |
| YouTube        | http://localhost:8003     |
| LLM            | http://localhost:8004     |
| Ollama         | http://localhost:11434    |

Swagger docs at `http://localhost:800{1,2,3,4}/docs` for each service directly, or route through the gateway.

## Data Models

### Authentication service

**`users`** — `id`, `email` (unique), `username`, `hashed_password`, `created_at`, `profile_pic`

### YouTube service

**`channels`** — `id`, `channel_id` (unique), `platform`, `channel_title`, `channel_handle` (unique), `subscriber_count`, `upload_playlist`

**`videos`** — `id`, `video_id` (unique), `video_title`, `video_description`, `published_at`, `channel_id_url`, `channel_db_id` (FK → channels, cascade delete)

**`video_metrics`** — `id`, `video_db_id` (FK → videos, cascade delete), `date`, `views`, `likes`, `comments_count`, `engagement_rate`; unique on `(video_db_id, date)`

**`comments`** — `id`, `comment_id` (unique), `video_db_id` (FK → videos, cascade delete), `published_at`, `author_name`, `like_count`, `text`

**`predicted_titles`** — `id`, `video_db_id` (FK → videos, cascade delete), `predicted_title`, `score`, `created_at`

### Reddit service

**`reddit_trending_posts`** — `id`, `post_id`, `title`, `subreddit`, `upvotes`, `num_comments`, `trend_score`, `url`, `cache_key`, `mode`, `fetched_at`; indexed on `cache_key` and `fetched_at`

## Known Gaps

- OTP is printed to stdout. There's no email delivery.
- The YouTube service DB connection retries forever on failure; there's no circuit breaker.
- Video ingestion fetches one playlist page — 20 videos per call.
- The gateway has no auth middleware. Token verification happens inside each upstream service, which means an unauthenticated request reaches the upstream before being rejected.
- The YouTube service still carries a `users` model and an `oauth.py` dependency. These are residue from the monolith and duplicate authentication logic that now lives in the auth service.
